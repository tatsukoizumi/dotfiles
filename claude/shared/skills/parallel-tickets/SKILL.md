# /parallel-tickets

チケット（Issue 番号 / チケット ID / 自由記述）を 2 件以上受け取り、それぞれを独立した worktree で並行実装する。

1. 各チケットの内容を把握する。Issue 番号なら `gh issue view` で読む。不明点が実装を左右する場合はここで確認する
2. チケット間で触るファイル・領域が重なるか事前に判定する。同一ファイル群を触る見込みなら並行ではなく直列実行を提案する
3. チケットごとに `ticket-worker` サブエージェントを 1 メッセージで並列起動する。各エージェントには以下を引き渡す:
   - チケットの内容と受け入れ条件
   - ブランチ命名（リポジトリ規約に従う。例: `feat/<番号>-<短い説明>`）
   - リポジトリの品質ゲートコマンド（lint / typecheck / test / ローカル CI 再現コマンド）
4. リポジトリに独自の worktree 慣習（/worktree コマンド、`.worktrees/<branch>/` 等）があればそれを尊重する
5. 全エージェントの報告を集約し、チケットごとに「ブランチ名 / 変更概要 / 品質ゲート結果 / 残課題」を一覧で報告する
6. マージ・PR 作成はしない。指示があった場合のみ次のステップに進む
